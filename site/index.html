Run one command on a machine and it shows up in your browser dashboard. Click it and you get a real interactive terminal — tabs, file transfer, live host stats — even when that machine sits behind NAT or a corporate firewall. 在一台机器上跑一条命令，它就出现在你的浏览器面板里。点开就是一个真正的交互式终端 —— 多标签、文件传输、实时主机状态 —— 哪怕这台机器藏在 NAT 或公司防火墙后面。

What you get你会得到什么

Not a log viewer. Your actual shell. 不是日志窗口，是你真正的 shell。

§ 01

A real terminal in the browser浏览器里的真终端

Full xterm.js: 256-color, resize, scrollback, copy/paste and Nerd Font icons — so a Powerline or Starship prompt looks the same as it does locally. 完整的 xterm.js：256 色、自适应尺寸、回滚缓冲、复制粘贴，还内置 Nerd Font 图标 —— Powerline / Starship 提示符和本地长得一模一样。

§ 02

All your machines, one dashboard所有机器，一个面板

Sign in with GitHub and every machine you've bound is listed with live status: online/offline, round-trip latency, CPU, memory and last-seen. 用 GitHub 登录，绑定过的机器全部在列，状态实时：在线与否、往返延迟、CPU、内存、最后一次心跳。

§ 03

See what each host is doing看清每台机器在忙什么

Without opening a shell: the foreground process of each session, how long it's been quiet, the busiest processes. Opt in and running Claude Code sessions show up too — what each one is working on, and whether it's mid-task or waiting on you. 不用开终端就能看到：每个会话的前台进程、空闲了多久、最占 CPU 的进程。开启开关后，正在跑的 Claude Code 会话也会出现 —— 它在做什么、正在执行哪个工具、是在干活还是在等你。

§ 04

Machines that reach each other机器之间互相可达

Not just browser→machine. switchboard nodes lists the others, exec runs something over there, shell opens a session. The agent on your laptop can drive the build box. 不只是「浏览器 → 机器」。switchboard nodes 列出其它机器，exec 在那边跑命令，shell 直接开会话。笔记本上的 agent 可以指挥编译机。

§ 05

Multiple shells, tmux-style多开会话，像 tmux

Open as many tabs as you want on one machine. Shells survive tab reloads and flaky links; in account mode they keep running after you close the browser. 同一台机器想开几个标签就开几个。刷新页面、断线重连都不会丢；账号模式下关掉浏览器它们还在跑，回来接着用。

§ 06

Drag-and-drop file transfer拖拽即传文件

Drop a file onto the page to upload it into the active shell's working directory, or pull any file off the host with a click. 把文件拖到页面上，就传进当前 shell 的工作目录；想取回主机上的文件，点一下就行。

§ 07

Works behind NAT穿透 NAT

The daemon dials out over WebSocket. No inbound ports, no firewall rules, no VPN, no tunnel to babysit. 守护进程通过 WebSocket 朝外拨号。不用开入站端口、不用改防火墙、不用 VPN，也没有隧道要盯着。

§ 08

Free at idle空闲时零成本

Built on Cloudflare's hibernatable WebSockets, so idle terminals cost nothing and the whole thing runs on the free Workers plan. 基于 Cloudflare 可休眠 WebSocket，空闲的终端不花钱，整套东西在 Workers 免费额度内就能跑。

§ 09

Self-hostable, end to end可自部署，端到端全是你的

The relay is a few hundred lines of Worker code, and the repo ships both ends. Deploy your own and own the entire stack. 中继只有几百行 Worker 代码，而且仓库里两端都有。部署到自己的账号，整条链路都归你。

Two ways to connect两种连接方式

Your machines, or a link you hand out. 自己的机器，或者发给别人的一条链接。

Both modes give you the multi-tab terminal and file transfer. They differ only in who can connect, and how long shells stick around. 两种模式都有多标签终端和文件传输，区别只在于谁能连进来，以及会话能留多久。

¶ the wire链路

Both ends dial out over WebSocket — keystrokes flow one way, terminal output the other. Nothing listens for inbound connections on your machine. 两端都通过 WebSocket 朝外连 —— 按键往一个方向走，终端输出往另一个方向回。你的机器上不监听任何入站连接。

¶ the operator接线员

idFromName(token-or-machine) funnels every daemon and browser on the same circuit into a single Durable Object — the operator that patches them together and broadcasts host output to every open tab. idFromName(token 或机器 id) 把同一路线路上的守护进程和浏览器都汇到同一个 Durable Object —— 由它把两端接通，并把主机输出广播给每个打开的标签页。

¶ the payload载荷

The relay is a transparent forwarder: it pairs the two ends and shovels frames between them. It never parses your terminal payload. 中继只是个透明转发器：把两端配对，然后来回搬运数据帧。它从不解析你的终端内容。

¶ the ledger账本

A small D1 database holds the bookkeeping — which machines belong to whom, hashed agent tokens, and the heartbeat behind the live dashboard. Terminal traffic never touches it. 一个小小的 D1 数据库只管记账 —— 哪台机器属于谁、哈希后的 agent token、以及支撑实时面板的心跳。终端流量完全不经过它。

Get started开始使用

Four steps, no deploy. 四步，不用部署。

This uses the hosted relay at shell.lfkdsk.org. Prefer to own it? Self-host the relay. 下面用的是托管中继 shell.lfkdsk.org。想自己掌握？看 自部署中继。

  1. 01

    Sign in from the machine在机器上登录

    It opens your browser, signs you in with GitHub, and exposes this machine's shell under your account — one step. 它会打开浏览器、用 GitHub 登录，并把这台机器的 shell 挂到你的账号下 —— 一步搞定。

    npx @switch-board/cli login
  2. 02

    Open the dashboard打开面板

    The URL it prints lists your machines. Click Open shell and you're in — tabs, file transfer, live stats. 命令打印出的地址会列出你的机器。点 Open shell 就进去了 —— 多标签、传文件、实时状态。

    https://shell.lfkdsk.org Open ↗打开 ↗
  3. 03

    Keep it running让它常驻

    Rather than leaving the CLI in a terminal window: the macOS menu-bar app on a Mac, a systemd user service on Linux. 别让 CLI 一直占着一个终端窗口：Mac 上用菜单栏 App，Linux 上装成 systemd 用户服务。

    switchboard service install
  4. 04

    Reach the other machines连到其它机器

    Sign in on two machines and each can see and drive the other — no browser in the middle, and it works to a host you couldn't ssh to. 两台机器都登录后，彼此都能看见、也能驱动对方 —— 中间不需要浏览器，而且对那些你 ssh 不到的机器同样有效。

    switchboard exec build-box npm test
